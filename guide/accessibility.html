Accessibility Guide

Accessibility (a11y) is a first-class citizen in Axon UI. By baking screen reader support, focus bounds, and WCAG rules directly into foundational layouts, we guarantee compliant application builds.

WCAG Standards

The Web Content Accessibility Guidelines (WCAG 2.2) categorize conformance rules into three levels:

  • Level A (Basic): Minimum web compatibility rules. (No keyboard trapping, keyboard accessibility).
  • Level AA (Standard): The target compliance level for commercial and enterprise platforms. Includes strict contrast limits:
    • Text Contrast: Minimum 4.5:1 for normal text (under 18pt) and 3:1 for large text (over 18pt or bold).
    • Non-Text Contrast: Minimum 3:1 for interface borders, buttons, and state indicators (active/focus boundaries).
  • Level AAA (Exceptional): Strict rules typically reserved for dedicated accessibility products (e.g. 7:1 text contrast).

ARIA Attributes (Roles, States, & Properties)

Accessible Rich Internet Applications (ARIA) attributes bridge the gap when semantic HTML5 elements are insufficient:

Attribute Type Purpose & Usage Example
role="dialog" Landmark Role Identifies container overlays as isolated dialogs.
aria-expanded State Indicator Set on accordion buttons ("true" | "false") to signal panel toggle states.
aria-controls Property Relation Points a trigger ID to the content pane ID it controls (e.g. tab -> panel).
aria-live="polite" Announcement property Announces visual mutations (such as notifications or alert updates) dynamically.

Keyboard Navigation & Tab Index

All interactive controls must be operable using a keyboard alone:

  • Focus Order: Keyboard focus must follow a logical reading order (typically top-to-bottom, left-to-right).
  • Tab Index Management:
    • tabindex="0": Places custom elements (like chips or badges) into the sequential keyboard tab flow.
    • tabindex="-1": Removes elements from tab flows, but allows programmatical focus shifts (e.g., focusing a modal container upon mount).
    • Positive tabindex: (e.g. tabindex="1") is an **anti-pattern**. It disrupts natural browser document focus flows.

Focus Management

Proper focus management ensures users navigating with tab keys or screen readers are never stranded:

  1. Skip Navigation Links: Add a hidden "Skip to main content" link at the top of pages that shifts keyboard focus directly past heavy header navigation menus.
  2. Focus Restoration: Always return focus to the trigger item after overlays, menus, or context popovers are closed.

Screen Reader Support

Visual indicators (like a trash can icon for delete actions) carry no meaning for visually impaired users. We must supply textual alternatives using **Visually Hidden helper classes**:

CSS
/* Visually hidden but readable by screen readers */
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}

Usage Example in React

React (IconButton)
import React from 'react';
import { Button } from './Button';

export const DeleteButton = () => {
  return (
    <Button variant="danger">
      <i className="fas fa-trash" aria-hidden="true" />
      <span className="sr-only">Delete client record</span>
    </Button>
  );
};
Decorative Icons Rule

Always add aria-hidden="true" to graphic icons, illustration glyphs, and font-awesome nodes. If an icon is decorative, hiding it prevents screen readers from announcing junk characters or filenames.

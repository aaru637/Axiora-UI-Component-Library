Design Tokens & Theming

Design tokens are the atomic visual values of a design system. By storing colors, typography scales, spaces, and motion parameters as variables, we decouple visual styles from code implementations.

Token Architecture

Axon UI uses a **three-tier token architecture** to ensure visual variables remain scalable and maintainable:

graph LR G[Tier 1: Global Tokens primitive values] --> S[Tier 2: Semantic Tokens contextual intent] S --> C[Tier 3: Component Tokens scoped bindings] subgraph Examples G1[ref.color.blue.50] --> S1[sys.color.brand.primary] S1 --> C1[comp.button.primary.bg] end style G fill:#93c5fd,stroke:#3b82f6 style S fill:#a7f3d0,stroke:#10b981 style C fill:#fef08a,stroke:#eab308
  1. Global Tokens (Primitives): Static, context-free design choices. These are values like blue-500: #3b82f6 or space-4: 1rem. They define the limits of the design palette but do not carry visual intent.
  2. Semantic Tokens (Contextual): System-level choices mapped to functional meaning. For example: color-background-primary = blue-50 (in light mode) and slate-900 (in dark mode). Semantic tokens handle light/dark adaptation automatically.
  3. Component Tokens (Scoped): Tokens scoped directly to a specific UI element. For example, button-primary-background = color-background-primary. Component tokens let you modify a button's padding or background color without affecting grids, cards, or inputs.

Design Tokens Reference

1. Typography & Font Scale

We declare font sizes as rem (relative em) values based on a standard 16px body base. This scales correctly when users adjust browser text zoom controls.

Token Name Rem Value Pixel Equivalent Usage Intent
--font-size-xs 0.75rem 12px Captions, helper texts, table cells
--font-size-sm 0.875rem 14px Standard button, inputs, secondary body
--font-size-base 1rem 16px Primary body paragraphs
--font-size-lg 1.125rem 18px Subheadings, prominent texts
--font-size-xl 1.25rem 20px Small headings (h4)
--font-size-2xl 1.5rem 24px Medium headings (h3)
--font-size-3xl 1.875rem 30px Section headings (h2)
--font-size-4xl 2.25rem 36px Page titles (h1)

2. Spacing Scale

Our spacing scale uses an 8px (0.5rem) baseline grid, with a 4px (0.25rem) half-step helper for compact layouts.

Token Value Usage Example
--spacing-1 0.25rem (4px) Checkbox labels gap, tiny paddings
--spacing-2 0.5rem (8px) Item lists gaps, standard element gap
--spacing-3 0.75rem (12px) Button inner margins, input paddings
--spacing-4 1rem (16px) Card layouts margins, stack spacing
--spacing-6 1.5rem (24px) Section margins, desktop paddings
--spacing-8 2rem (32px) Widescreen container grid gaps

3. Shadows & Elevation

Shadow values create visual hierarchy and depth. In dark mode, shadow values must be reduced in opacity and combined with light borders to create a realistic elevation effect.

CSS
:root {
  --shadow-sm: 0 1px 2px 0 rgba(0, 0, 0, 0.05);
  --shadow-md: 0 4px 6px -1px rgba(0, 0, 0, 0.1), 0 2px 4px -2px rgba(0, 0, 0, 0.1);
  --shadow-lg: 0 10px 15px -3px rgba(0, 0, 0, 0.1), 0 4px 6px -4px rgba(0, 0, 0, 0.1);
}

[data-theme="dark"] {
  --shadow-sm: 0 1px 2px 0 rgba(0, 0, 0, 0.5);
  --shadow-md: 0 4px 6px -1px rgba(0, 0, 0, 0.4), 0 2px 4px -2px rgba(0, 0, 0, 0.4);
}

4. Breakpoints & Motion

Breakpoints determine responsive layout shifts. Motion defines our duration and easing variables:

  • Breakpoints: Mobile (320px), Tablet (768px), Desktop (1024px), Widescreen (1440px).
  • Transitions: Fast (100ms for button hovers), Normal (200ms for toggles/dropdowns), Slow (300ms for overlays/drawers).
  • Easing: Ease-in-out (cubic-bezier(0.4, 0, 0.2, 1)).

Theme System Configuration

Themes are implemented by swapping CSS custom properties at the top-level <html> element. This allows theme switching without causing DOM flashes or page updates:

Token Code Example (JSON source)
{
  "color": {
    "brand": {
      "primary": {
        "value": "{ref.color.blue.500}",
        "attributes": {
          "category": "color"
        }
      }
    }
  }
}
Dark Mode Contrast

Always ensure text elements meet WCAG AA requirements (minimum 4.5:1 ratio) in dark mode. Pure white text (#ffffff) on dark backgrounds can cause eye strain; use a slightly muted off-white (like #f8fafc or #e2e8f0) for headers and paragraphs instead.

Project Setup Guide

Building a robust UI Component Library requires a stable engineering environment. This section guides you through setting up a modern monorepo workspaces environment and configuring the essential toolchain.

Prerequisites & Node.js Setup

Before initializing the project, ensure your development machine meets the following environment baselines:

  • Node.js: Active LTS version (v20.x or higher recommended). Verify your local setup using node -v.
  • pnpm: We select **pnpm** as our default package manager. pnpm uses a content-addressable store to reduce disk footprint, provides fast dependency installation speeds, and enforces strict dependency isolation in monorepos. Install it globally using:
Terminal
npm install -g pnpm

Package Manager Selection: Why pnpm?

In a UI library, managing dependencies efficiently is vital. Traditional packages managers like npm or yarn v1 install dependencies in a flat node_modules tree. This flat layout enables phantom dependencies—where components can import packages not explicitly declared in their local package.json because they are hoisted from other packages. pnpm solves this by using symlinks to construct a strict node_modules hierarchy, ensuring each package only has access to imports it explicitly declares.

Monorepo vs. Single Package

For an enterprise UI suite, we highly recommend a Monorepo structure over a monolithic single package. Here is why:

Monorepo Architecture Single Package (Monolith)
Split into discrete packages (e.g., @axon/tokens, @axon/react, @axon/icons). Everything bundled into a single NPM entry point.
Pros: Independent versioning, product teams can import *only* tokens without importing React runtime. Clean code boundaries. Pros: Simple setup, single package to maintain.
Cons: Marginally more complex build pipeline configuration. Cons: Bloated bundles, harder to scale, forces updates of everything at once.

Project Initialization

Let's initialize a new monorepo workspace. Create a directory named axon-ui and set up the workspaces structure:

Terminal
mkdir axon-ui && cd axon-ui
pnpm init

Create a pnpm-workspace.yaml file in the root to define package boundaries:

pnpm-workspace.yaml
packages:
  - 'packages/*'
  - 'apps/*'

Now create the standard folder structure inside your workspace directory:

Terminal
mkdir -p packages/tokens packages/react packages/icons apps/storybook

Recommended Technology Stack

To deliver a state-of-the-art developer experience, Axon UI is built on top of the following stack:

  • React (v18+): The core rendering engine, utilizing functional components and hooks.
  • TypeScript (v5+): Enforces strict interface contracts and provides rich editor autocomplete.
  • Vite: The extremely fast bundling engine that powers local component compiling and hot module replacement.
  • Storybook: A sandboxed playground environment for writing, documenting, and visually validating UI components.
  • Vitest: A modern testing framework designed to run with Vite, enabling fast unit and component integration tests.
  • ESLint & Prettier: Automate code linting and style formatting to ensure a unified style footprint across developers.
  • Husky: Manages Git Hooks (e.g., pre-commit hooks) to run type checkers and format tests prior to push.
  • Changesets: A multi-package tool that automates semantic version management, changelog generation, and NPM publish operations.

Tool Configuration

1. Linting & Formatting

Create a root .prettierrc file to standardize code formatting:

.prettierrc
{
  "semi": true,
  "trailingComma": "all",
  "singleQuote": true,
  "printWidth": 100,
  "tabWidth": 2
}

2. Husky Git Hooks

Install Husky in the root workspace to run validation checks before commits are pushed:

Terminal
pnpm add -wD husky
pnpm exec husky init

Inside .husky/pre-commit, add the linting validation action:

.husky/pre-commit
pnpm run lint
pnpm run type-check

3. Changesets Integration

Changesets helps manage versions and changelogs. Initialize it in the root workspace:

Terminal
pnpm add -wD @changesets/cli
pnpm changeset init

This creates a .changeset/config.json file. Ensure the release configuration is set to link related packages and configure repository access prior to your first commit.

Pro Tip

Always run install scripts from the root directory using pnpm install. In a workspaces setup, installing dependencies in nested directories directly can break the content-addressable link cache and lead to duplicate dependencies.

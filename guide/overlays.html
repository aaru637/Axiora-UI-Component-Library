Overlay Components

Overlay components render content floating above the primary document layout. Because overlays break the default HTML flow, they require strict attention to focus state management, event capturing, and portal rendering.

Portal Implementation

In HTML layouts, setting overflow: hidden or custom z-index styling on parent cards can clip or obscure floating elements. To prevent this, all overlays must utilize React Portals to render their HTML tree at the bottom of document.body, while retaining React event propagation behavior.

Portal.tsx
import { ReactNode } from 'react';
import { createPortal } from 'react-dom';

export const Portal = ({ children }: { children: ReactNode }) => {
  if (typeof window === 'undefined') return null; // Hydration guard
  
  let portalRoot = document.getElementById('axon-portal-root');
  if (!portalRoot) {
    portalRoot = document.createElement('div');
    portalRoot.id = 'axon-portal-root';
    document.body.appendChild(portalRoot);
  }
  
  return createPortal(children, portalRoot);
};

Focus Management & Keyboard Navigation

An overlay dialog must implement three core keyboard behaviors to meet accessibility standards:

  1. Focus Restoration: When the overlay opens, it shifts focus inside the modal. When it closes, it returns focus to the trigger button that opened it.
  2. Focus Trapping: The Tab key must cycle focus only through active elements inside the overlay. It must block focus from escaping into background links.
  3. Dismiss Key: Pressing Escape must trigger the overlay close callback immediately.

React Focus Trap Hook

useFocusTrap.ts
import { useEffect, useRef } from 'react';

export const useFocusTrap = (isActive: boolean) => {
  const containerRef = useRef<HTMLDivElement>(null);

  useEffect(() => {
    if (!isActive) return;

    const handleKeyDown = (e: KeyboardEvent) => {
      if (e.key !== 'Tab') return;
      
      const container = containerRef.current;
      if (!container) return;

      const focusables = container.querySelectorAll<HTMLElement>(
        'button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])'
      );
      
      const first = focusables[0];
      const last = focusables[focusables.length - 1];

      if (e.shiftKey) {
        if (document.activeElement === first) {
          last.focus();
          e.preventDefault();
        }
      } else {
        if (document.activeElement === last) {
          first.focus();
          e.preventDefault();
        }
      }
    };

    document.addEventListener('keydown', handleKeyDown);
    return () => document.removeEventListener('keydown', handleKeyDown);
  }, [isActive]);

  return containerRef;
};

Component Reference

1. Modal & Dialog

A modal interrupts the main application flow. It displays a semi-transparent dark backdrop overlay and requires user action to dismiss.

  • Role: role="dialog" and aria-modal="true".
  • Labeling: Link the modal title element to the dialog container using aria-labelledby="[title-id]".

2. Drawer

Drawers act as slide-out overlays that anchor to the sides of the screen (typically left or right). They are ideal for responsive search panels or navigation menus.

3. Popover & Tooltip

  • Popover: Rich interactive panels anchored to a target node. They can contain forms and buttons. Click outside to dismiss.
  • Tooltip: Brief, text-only descriptions that render on hover or keyboard focus. Tooltips should have role="tooltip" and link with target buttons using aria-describedby.
Tooltip Delay Requirement

Never show tooltips instantly on mouse hover. Apply a standard delay of 300ms - 500ms. This prevents the viewport from flashing tooltips when users sweep their cursor across navigation grids.

4. Dropdown & Context Menu

Dropdowns display context lists of actions. They must support vertical arrow key navigation (using ↑ and ↓), selecting options with Enter or Space, and autoselect match matching.

Enterprise Scaling Guide

Scaling a UI Component Library across dozens of product teams and hundreds of applications requires robust tool caching, design governance, and contribution loops.

Monorepo Strategy (Turborepo)

To speed up compile, lint, and test tasks in a monorepo workspace, we integrate **Turborepo** (or Nx). Turborepo caches task outputs. If a component's code has not changed since the last build, Turborepo skips compiling it, reducing CI build times by up to 90%.

Example Cache Configuration

turbo.json
{
  "$schema": "https://turbo.build/schema.json",
  "pipeline": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**", ".next/**"]
    },
    "test": {
      "dependsOn": ["build"],
      "outputs": []
    },
    "lint": {
      "outputs": []
    }
  }
}

Package Boundaries

Isolate structural elements from presentation templates using strict package boundaries:

  • Shared Utilities (@axon/utils): Code-only helpers (such as focus ring class builders or validation scripts).
  • Shared Hooks (@axon/hooks): Headless React helpers (such as useOutsideClick, useMediaQuery).
  • Shared Themes (@axon/themes): Color variables, dark mode styles, and brand logo packages.

Design Governance & Figma Sync

Design drift occurs when design files and codebases fall out of sync. To resolve this, we enforce a strict token sync pipeline:

By automating token compilation through GitHub Actions, updates to colors or spacing inside Figma can be pushed directly to the codebase via pull requests, keeping design and code in sync automatically.

Contribution Workflow

Product teams should not modify the core library directly. Instead, they should submit requests and follow our contribution workflow:

  1. Open Proposal Issue: Explain the feature request or bug report with mockups and architectural reasoning.
  2. Create Feature Branch: Fork the library repository and build code in accordance with our dev standards.
  3. Write Stories & Tests: Supply corresponding Vitest tests and Storybook playgrounds.
  4. Submit Pull Request (PR): PR triggers automated CI pipelines (lint check, unit tests, Chromatic visual checks).
  5. Governance Review: The core UI maintainer team reviews code before merging updates into the primary branch.
Branching Warning

Never bypass PR checks or force-push updates to the primary branch. Product applications rely on the stability of the UI library; even small stylesheet overrides can cause widespread layout breaks.

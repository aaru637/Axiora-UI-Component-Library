Build & Publish Guide

To ensure clean consumption across different JavaScript runtimes and module bundlers, our build system outputs multiple format configurations while optimizing for file size.

ESM vs. CommonJS Compilation

Modern frontend bundlers (like Vite, Webpack 5, and Rollup) consume **ES Modules (ESM)**. However, legacy server rendering pipelines and Node.js testing environments still rely on **CommonJS (CJS)**. To support both, we compile our TSX files into two separate output distributions: dist/index.mjs (ESM) and dist/index.cjs (CJS).

Package Exports Mapping

In modern package compilation, we configure the exports map inside package.json to declare module entry points explicitly. This directs modern bundlers to import ESM files while routing legacy tools to CJS files:

package.json
{
  "name": "@axon/react",
  "version": "1.4.2",
  "main": "./dist/index.cjs",
  "module": "./dist/index.mjs",
  "types": "./dist/index.d.ts",
  "sideEffects": [
    "**/*.css"
  ],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.mjs",
      "require": "./dist/index.cjs"
    },
    "./package.json": "./package.json"
  }
}

Tree Shaking Configuration

By declaring "sideEffects": ["**/*.css"], we tell client-side compilers that our JavaScript components do not run code upon loading. This enables Webpack and Vite to perform **Tree Shaking**—completely dropping unused components from the client application's bundle.

Release Management (Changesets)

We manage package versions and publishing pipelines using **Changesets**. This tool automates SemVer (Semantic Versioning) upgrades and changelog generation:

Release Workflow Steps

  1. Add Changeset: When submitting code updates, run the changeset CLI tool to declare the release classification (major, minor, or patch) and add description notes:
    2. Terminal
    pnpm changeset
  2. Commit: Commit the generated markdown file inside .changeset/ alongside your changes.
  3. Release Bump: During the release pipeline, compile the changesets to bump package versions:
    4. Terminal
    pnpm changeset version
  4. Publish: Build all workspace packages and publish updates to the NPM registry:
    5. Terminal
    pnpm build
pnpm changeset publish
Security Token Publishing

Always publish NPM packages from secure CI systems (like GitHub Actions) using granular access tokens. Never publish packages directly from developer terminals, as this exposes credentials to potential token theft.
